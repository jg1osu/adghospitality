3. Deploy on Vercel with reliable email delivery

Vercel hosts the site; HostGator can retain your domain, DNS and email. Vercel’s Hobby plan is for personal, noncommercial use; choose an eligible commercial plan for ADG.

  1. Import the source repository into Vercel. Select the branch containing this website and the project root. Use “Other” framework, npm run build, output dist, and Node 22 or newer. There are no packages to install.
  2. Create a Resend account, verify a sending domain and publish its DNS records. Use a real domain sender such as website@adghospitality.com. See Resend domain verification.
  3. Add production environment variables in Vercel: RESEND_API_KEY (secret), INQUIRY_TO_EMAIL=alisa@adghospitality.com, INQUIRY_FROM_EMAIL=website@adghospitality.com. Optional INQUIRY_SITE_ORIGIN=https://adghospitality.com restricts browser origin; omit while testing on temporary Vercel domains. Never add these values to public configuration or Git.
  4. Set inquiryEnabled: true in site.config.mjs. Keep inquiryEndpoint: '/api/inquiry'. Deploy, submit a real test from the website, confirm receipt in Alisa’s inbox and test Reply.
  5. If credentials are missing, the endpoint returns an error; it does not pretend an email was sent. Failures leave visitor form entries intact. Resend receives the retry UUID to suppress accidental duplicate sends within its idempotency window.

4. Alternative: host the site itself on HostGator

Use this alternative if you want HostGator to serve the website. Vercel deployment does not transfer the site to HostGator. HostGator shared hosting does not run this Node endpoint; the supplied PHP endpoint provides the mail path.

  1. Copy hostgator/config.example.php outside the public document root to /home/YOUR_ACCOUNT/adg-inquiry-config.php. Do not upload that config into public_html. Set the actual recipient, domain sender and site origin. Restrict file permissions to 0600.
  2. Create a dedicated private writable directory /home/YOUR_ACCOUNT/adg-inquiry-state with permissions 0700, then set its absolute path as state_dir. This enables retry deduplication. Leave unrelated application files out of this directory.
  3. Ensure the sender mailbox exists and SPF/DKIM are configured. HostGator’s PHP mail() must be enabled. PHP mail acceptance is not proof of inbox delivery; test both.
  4. Set inquiryEnabled: true, add your calendar URL, and run node scripts/build.mjs --hostgator.
  5. Upload the contents of work/hostgator-dist into your domain’s document root, normally public_html, including .htaccess and inquiry.php. The build changes the public endpoint to /inquiry.php.
  6. Test real delivery and every page over HTTPS. Confirm directory-index behavior, no listing of directories, privacy page and mobile menu.

The included HostGator ZIP reflects the current draft settings. Regenerate it after activation. No PHP runtime was available during this build, so native PHP lint and live HostGator mail tests remain outstanding.

5. The free chat assistant

The included “A little guidance” widget is a scripted, browser-only FAQ assistant. It answers package, guest, license and rain questions and directs visitors to Alisa or scheduling. It requires no subscription, API key, account or chat storage. It does not claim to know live wedding availability or generate AI answers.

6. Make the site visible to search engines

The build includes unique titles and descriptions, canonical URLs, share metadata, Organization/Service/FAQ/Breadcrumb structured data, robots.txt and a sitemap. Content covers Charleston elopement packages, how to elope, costs and locations. Local fonts and optimized WebP images keep the site lightweight. These foundations support relevance; rankings and FAQ rich results are not guaranteed.

  1. Approve accurate services, prices, venue restrictions and the privacy notice; activate and test mail and calendar.
  2. Replace generated imagery with licensed photographs of your real work where possible, obtain any necessary couple permissions and write accurate image descriptions. Never present illustrative scenes as previous ADG weddings or specific partner venues.
  3. Set launchReady: true and siteUrl to the final HTTPS domain. Rebuild/redeploy. Check robots.txt now says Allow and every page’s robots tag says index, follow.
  4. Verify the domain in Google Search Console and submit https://adghospitality.com/sitemap.xml. Request indexing for the homepage and useful guides.
  5. Create or improve an eligible Google Business Profile with consistent business name, contact and service area. Use a real business location and do not fabricate an address for schema.
  6. Add a truthful about page with Alisa’s background, real portfolio stories and genuine client reviews when available. Ask real clients for reviews; none are invented on the current site.
  7. Build real relationships with local venues and vendors for relevant referrals and links. Keep legal/location information current and publish original examples from completed work.

There is no analytics or advertising tracking by default. Add privacy-appropriate measurement after launch to track actual inquiries and bookings rather than page visits alone.
